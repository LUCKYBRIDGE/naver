각 시험에 다음 항목을 남긴다.


사용자 모드 관찰 도구가 모든 순간을 포착한다고 주장하지 않는다. 사용한 이벤트·샘플링 주기·관찰 오차를 기록하고, 시각 관찰·시험 수신기의 입력 결과와 대조한다.

## 3. P1a: 웨일 입력 전달이 교사 작업을 유지하는가?

1. 대상 웨일 창의 시험 페이지를 표시한다. 별도의 교사 작업 창을 활성화한다.
2. CDP 프로브에서 선택한 탭에 클릭·휠·드래그·문자 삽입·Backspace·Enter를 전달한다.
3. 교사는 메모장에서 알려진 문장을 입력하고 물리 마우스로 선택·드래그한다.
4. 같은 시험을 한글 IME 조합 중, 다른 웨일 창에서 입력 중인 상황으로 반복한다.
5. 페이지 내부 선택·입력 대상은 학생 목표로 바뀌지만 Windows foreground와 교사 입력 대상은 바뀌지 않아야 한다.
6. DOM 이벤트 종류·isTrusted·기본 동작·실제 값을 기록한다. API 호출 성공 응답만으로 입력 성공을 판정하지 않는다.
7. DevTools 열기, debugger 해제, 정책 차단, 탭 닫기·탐색 후 실패 처리도 확인한다.

합격: 대상 웹페이지에서 동작·입력이 확인되고 교사 커서·포커스·문자에 학생 때문에 발생한 변화가 0건. 임시 창 활성화·커서 복원·전역 키 입력 없이 통과해야 한다.

## 4. P1b: 실제 전자칠판 입력을 격리할 수 있는가?

- 먼저 차단 없는 관찰 상태에서 마우스·터치·펜 이벤트와 포커스·커서 변화를 기록한다.
- 후보 A와 B를 각각 독립 실행해 실제 전자칠판 터치 100회, 이동·드래그·길게 누르기를 시험한다.
- 교사 마우스 정지 상태에서 위치와 표시 상태를 관찰하고, 물리 마우스 이동·클릭·드래그 중에도 반복한다.
- B에서는 수신 창이 터치를 받으면서 물리 마우스를 통과시키는지, 투명 영역도 실제로 hit-test 되는지, 학생 가상 키보드 영역도 포함하는지 확인한다.
- 둘 이상의 터치/펜 장치, 일반 마우스로 보고되는 전자칠판, USB 끊김을 시험한다. 구분 불가능한 입력을 임의로 차단하지 않는다.
- `GetCursorInfo`의 위치·표시·억제 상태와 foreground 변경 이벤트를 대조한다. OS 터치에 의한 `CURSOR_SUPPRESSED`는 훅이 클릭을 막았어도 실패다. [Microsoft CURSORINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-cursorinfo)

합격: 사용자 요구 R1~R4 통과와 교사 물리 마우스의 누락·먹힘 0건. 원래 포인터가 웨일에 도달해 중복 클릭되는 현상 0건. 실패 후보는 채택하지 않는다.

## 5. P2/P3: 연결·좌표·독립 마우스

| 조건 | 확인할 결과 |
|---|---|
| 클릭·더블클릭·학생용 포인터 표시 | 정확한 대상 1회 실행, 시스템 커서 비변경 |
| 캔버스·슬라이더·텍스트 선택 드래그 | down/move/up 순서, 실제 drag 결과, 중복 없음 |
| 포인터 영역 이탈·손가락 취소 | release/cancel, 버튼 눌림 상태가 남지 않음 |
| 중첩 스크롤 영역 | 목표 영역 이동, 교사 창은 스크롤되지 않음 |
| 100/125/150% DPI, Whale 80/100/125% zoom | 모서리·중심 교정 오차 초기 목표 4 CSS px 이하, 실제 작은 대상 명중 |
| 음수 화면 좌표·화면 번호 변경 | 목표 디스플레이와 좌표가 일치 |

| 같은 PC 다른 Whale 창·탭 | 학생 탭만 조작, 교사의 활성 탭을 따라가지 않음 |
| SPA 이동·새 문서·iframe | 이전 편집 대상 폐기, 지원 가능한 문서에만 동작 |
| 최소화·가림·잠금·화면 분리 | 보이지 않는 탭으로 클릭 전송 중단 |
| 오래된 seq·잘못된 세션·범위 밖 좌표 | 거부, 대상 선택을 메시지로 임의 변경할 수 없음 |

iframe/OOPIF는 별도 시험한다. top-level 페이지 통과를 전체 프레임 지원으로 간주하지 않는다.

## 6. P4: 가상 키보드

순수 조합기 시험과 실제 Whale 편집 시험을 분리한다.

- 한글: 세종대왕, 학교, 값, 앉아, 읽어, 과외, 의자, 쌍자음·겹받침·이중모음.
- 조합 중 Backspace로 음소를 단계적으로 삭제하고, 확정된 음절 삭제와 구분.
- 한/영·Shift·숫자·공백·Enter, 연속 입력, 선택 범위 교체, caret 중간 삽입.
- input·textarea, maxlength·읽기 전용·비활성 입력, 프레임워크 제어 입력.
- 입력란 변경·페이지 이동·OFF·연결 끊김 중 미확정 글자 처리.
- 키보드 버튼을 눌러도 학생 편집 대상 유지. 교사 한글 조합 도중 학생의 한/영·Shift가 교사 IME·물리 키 상태를 바꾸지 않음.
- contenteditable·리치 편집기·캔버스 입력은 별도 지원 행으로 기록. 지원하지 않으면 안내.
- password·file·인증·결제 입력에는 키보드와 입력 엔진을 적용하지 않음.

합격: 결과 문자열·selection이 기대값과 일치하며 교사 쪽 문자 누락·중복·학생 문자열 유입 0건. 합성 이벤트 호출 여부만 검증하는 테스트 대신 실제 입력 결과를 검사한다.

## 7. 비상 해제와 수명주기

시험 대상: OFF, F9, F9 등록 충돌, Native 정상 종료/강제 종료/응답 멈춤, 호스트 중복 실행, Native port 단절, Worker 중지·재시작, debugger 분리, 탭/창 종료, USB 끊김, 화면 잠금·절전·복귀.

정상 해제의 초기 반응 목표는 250ms 이내, 연결 무응답은 2초 이내 해제다. 내부 목표이며 실제 결과를 기록해 조정한다. 해제 뒤 교사·전자칠판 일반 입력이 모두 정상이어야 한다. 재연결·재시작 때 자동으로 ACTIVE를 복원하지 않는다.

수신 창·후크가 남아 입력을 먹거나 일반 키보드 입력을 막으면 실패다. 실패를 교사 커서·포커스 강제 복원으로 감추지 않는다.

## 8. 성능·동시성

- 기준 상태와 활성 상태를 동일 조건으로 비교한다. 입력 중 장치 관찰 도구의 부하도 별도 측정한다.
- 교사 입력: 물리 마우스·키보드 누락 0, 업무 창의 시각적 지연 악화 여부 확인. 훅 후보 콜백 p99 1ms 이하를 초기 내부 목표로 잡되 end-to-end 무지연 증명으로 해석하지 않음.
- 학생 입력: 수신부터 페이지 반영까지 p95 50ms·p99 100ms 이하를 초기 목표로 기록. 프로세스 간 시계 기준을 맞추고 UI 반영 시점도 확인.
- CPU·메모리·큐 길이·전송량·GC pause를 OFF/유휴/터치 연속/키보드 연속에서 기록. OFF에서는 기능에 의한 반복 입력 감시가 없어야 함.
- 별도 두 시험자로 60초 기본 동시 입력, 10분 반복 조작, 30분 수업 모사 순으로 진행.
- 교사 메모장·한글·PPT·다른 Whale 창에서 각각 확인. 교사가 스스로 바꾼 포커스와 학생 때문에 바뀐 포커스를 구분.
- 복제 화면에서는 보이는 창 배치 조건을 함께 기록. 가려진 학생 페이지를 조작하는 시험을 정상 사용으로 취급하지 않음.

## 9. 설치·권한·실제 사이트

- MV3 로드, Manifest 경고, 아이콘, Worker 오류, sidebar_action 단독 선언 확인.
- Native 등록·제거·확장앱 ID 변경, 관리자 권한 없는 실행, 학교 정책 제한 시험.
- 원래 페이지 CSS·기능·키보드 접근성, 가상 키보드 열림·닫힘, 작은 화면·사이드바 폭 확인.
- 불필요한 권한·광범위 자동 주입 제거, 실제 사이트 허용 범위와 사용자 설명 일치 확인.
- 허용된 공개 페이지 → 실제 웨일 클래스/팀보드 기능 순으로 확인. 업무·학생 개인정보 화면은 진단 로그에 남기지 않음.
- 확장앱 파일과 호스트 패키지의 역할·설치 안내·실제 경로가 일치해야 함.

## 10. 현재 시험 결과

### 2026-10-07 macOS 개발 검사

- 로컬 복제 후 `git fsck --full` 통과. 외장 볼륨의 반복 연결 중단 뒤 저장된 파일을 확인하고 검사를 재실행했다.
- Node.js 24.19.0. `npm test`: 14개 통과, 0개 실패, 종료 코드 0.
- `npm run build`: JavaScript 문법·MV3 리소스 검사와 제품/프로브 분리 출력, 종료 코드 0.
- Chrome 155.0.8059.40, headless 1280×800, `http://127.0.0.1:8765/p1a.html`, Playwright CDP 전송으로 입력 엔진 검사.
- 결과: clicks=1, drags=1, scrollTop=160, input=`한글 ABC 12`, textarea=`한글 ABC 12`+줄바꿈. 별도 탭에 자동 입력한 교사 시험 문자열은 일치. 페이지 오류·콘솔 오류 0.
- 이 검사는 `whale.debugger`/`chrome.debugger` 확장앱 연결이나 물리 키보드를 사용하지 않았다. headless 브라우저의 탭 입력을 Windows 비활성 창/foreground 시험으로 해석하지 않는다. pageHasFocus 관찰값도 OS foreground 증거가 아니다.
- 실험 소스가 제출 ZIP에 섞이지 않도록 기존 `package-project whale-dual-input` 명령이 의도적으로 종료 코드 1로 차단되는 것을 확인했다.

실제 Whale 버전·전자칠판·Windows 입력 보호 결과는 미기록이다. 위 P0~P5 실기기 시험 행은 모두 미실시로 유지한다. [P1A_RUNBOOK](P1A_RUNBOOK.md)으로 Windows Whale에서 P1a를 먼저 실행하고, P1b 장치 관찰·격리 실험을 이어간다. 학교 PC/웨일북 성능과 Windows 입력 격리는 완료로 표시하지 않는다.
