# M0.5 장치·입력 관찰 결과

2026-10-13. 코드: `codex/monitor1-input-probe` 작업 트리, Probe 연구 구현 0.1. **원본 격리·G1/G2 통과 결과가 아니다.** 사용자의 실제 전자칠판 터치와 도구의 관측, 사용자 진술을 구분한다.

## 자동 조회

- 데스크톱 영역 2개: 주 화면 (0,0) 1920×1080 / 보조 화면 (1920,0) 1920×1080, DPI 96/96, 회전 identity.
- `GetPointerDevices`/`GetPointerDeviceRects`: 보조 화면 TOUCH 최대접촉 40, 주 화면 TOUCH 최대접촉 10 및 PEN_INTEGRATED 최대접촉 1을 반환했다.
- `QueryDisplayConfig`: 동일 source에 복수 출력 경로가 관측되어 DISPLAY_CLONE_DETECTED. 화면 영역 2개라는 사실만으로 물리 디스플레이 출력 모두가 독립 확장이라고 판단하지 않는다.
- 출력 그룹 수를 추가한 후 읽기 전용 재조회에서 주 화면 PhysicalTargetPaths=1, 보조 화면 PhysicalTargetPaths=2를 확인했다. 보조 데스크톱 하나가 두 출력 대상에 연결된 구성이다. 각각의 물리 패널/연결 명칭은 아직 대조하지 않았다.
- Raw Input에는 HID/Mouse/Keyboard 유형이 열거됐다. 키보드는 목록 유형만 확인하고 이벤트를 등록·파싱하지 않았다. Mouse/Pointer 핸들이 같은 물리 장치를 나타내는지 대조하지 않았다.
- 장치 제조사·모델·물리 연결·다른 포인터의 실제 사용 여부는 별도 확인 전이다. QueryDisplayConfig로 복제 source 그룹은 구분했으나 어느 물리 패널인지 특정하지 않았다.

## 실제 관찰 세션 — 사용자 제공 카운터

사용자는 전자칠판에서 여러 번 터치·드래그를 수행하고 아래 카운터를 전달했다. 사용자가 혼자 시험했으며 교사의 물리 타이핑과 학생 터치를 두 명이 동시에 수행한 시험이 아니다. 팝업 안/밖·정확한 횟수/기간을 분리한 공식 G1 시나리오가 아니었다.

|---|---:|---|

사용자는 '마우스 납치되는거 같아'라고 보고했다. 이는 **차단 없는 관찰 상태에서 일반 Windows 입력 간섭이 있었다는 사용자 관찰**이다. 사용자 보고와 CURSOR/FOCUS 카운터만으로 간섭의 정확한 횟수·장치·시각을 확정하지 않는다.

## 수정한 관찰 도구 문제

1. 첫 버전은 읽기 전용 관찰에도 복제/조회 조건을 적용해 시작을 거부했다. 관찰과 차단 시험의 조건을 분리했다.
2. Raw Input 등록의 초기 장치 알림을 종료로 처리해 시작/종료 각 9회의 짧은 세션이 생겼다. 관찰은 알림을 기록하며 유지하고, 차단 시험에서는 이미 열거한 장치의 초기 arrival만 제외한 실제 변경에 중지하도록 수정했다.
3. 관찰/성공 혼동을 줄이기 위해 '터치 차단 없음·커서 납치 가능', 팝업 안/밖의 관측 범위를 표시한다. 현재 불완전 구성에서 차단 시험 버튼을 비활성화했다.

## 판정

- 장치 및 입력 수신: 표준 터치 매핑 조회·직접 터치 수신·학생 접촉 채널 동작을 관측했다.
- M0.5 계측 완성: **부분 구현**. 아직 Raw HID 해석·Pointer/Raw 물리 장치 대조·출처별 간섭 자동 귀속·교사 동시 타이핑·오탐/미탐 검증이 남아 있다.
- 원본 입력 격리: **미실행/미증명**. 관찰 모드는 어떤 입력도 차단하지 않는다.
- G1/G2: **NOT TESTED**. 학생 팝업 내부 이벤트 수신이 교사 보호나 Whale 웹 입력의 통과 증거가 아니다.
- 다음: 복제 출력의 실제 그룹과 주 화면 터치·펜의 물리 구성을 확인한다. 학생 칠판 장치 전체의 원본 차단 경로를 선택하고, 전달 없이 차단만 시험한 뒤 Whale에 연결한다. 화면 구성이나 다른 터치를 임의 변경하지 않는다.
