# Windows 입력 분리 연구 도구 사용법

2026-10-13. 도구 버전: 연구 구현 0.1. **제품 보호 엔진이 아니며 G1/G2 미검증**이다. 이 도구는 학생 입력 채널을 만들기 전 장치/화면 경로와 차단 후보를 계측한다. 기존 v0.2.0 확장·Native Host와 동시에 실행하지 않는다.

2026-10-14: 별도 [원본 터치 격리 연구 backend](ISOLATION_A_IMPLEMENTATION.md)를 추가했다. 일반 Probe에는 `원본 터치 격리` 버튼의 자격/매핑 검사를 넣었으며 실제 UIAccess 토큰이 없으면 비활성화된다. `--isolation-capabilities`는 등록 없이 이유만 조회한다. 관찰과 마우스 차단 후보의 기존 동작은 유지한다. 현재 기기에서는 UIAccess 부재·복제/다른 터치 조건으로 원본 격리 시험을 시작하지 않는다.

## 구현된 기능

- QueryDisplayConfig와 모니터 정보를 대조해 확장/복제·주/보조 화면·음수 좌표·DPI·회전을 진단한다.
- GetPointerDevices/GetPointerDeviceRects로 표준 터치·펜의 Windows 매핑을 읽고, Raw Input 장치 유형 및 HID Usage를 조사한다. 제조사 선택·수동 화면 영역 지정은 없다.
- 키보드를 등록하지 않는 Raw Input 수신, 커서 4ms 목표 샘플링, 전경/내부 포커스 이벤트와 샘플링, 마우스 훅 좌표·터치/펜 유래 호환 마우스 서명을 관측한다.
- 보조 화면의 별도 시험 창에 도달한 직접 포인터와 절대좌표 Raw Mouse 후보를 표시한다. 상대좌표 마우스는 임의로 칠판으로 지정하지 않는다.
- 매핑된 직접 터치·펜은 연구용 SeatEventV1 채널에서 장치별 접촉 ID·누름/이동/해제/취소를 관리한다. 큐 128개·동시 접촉 32개 상한, 혼잡·영역 이탈·종료 시 취소를 처리한다. isolationEvidence는 항상 NONE이다.
- 명시적 30초 차단 후보 ON: 주 화면 커서 제한 + 주 화면 밖/터치·펜 호환 마우스 메시지 차단을 시험한다. F9, 모니터 1 OFF, 시간 만료, UI 응답 중단, 장치/화면/세션 변경에서 정리한다.
- 모든 보호 표시는 EXPERIMENTAL/미검증이다. 웹 입력·Native 브리지·자동 G1 합격 판정은 연결하지 않았다.

## 빌드·실행

Node.js 24 및 .NET 10 SDK가 필요하다. 다른 npm 라이브러리는 필요하지 않다.

```powershell
npm run build:input-probe
& .\dist\whale-dual-input\input-probe\WhaleDualInput.Probe.exe
```

EXE는 win-x64 자체 포함이며 SDK 없는 시험 PC에도 `input-probe` 출력 폴더를 복사해서 실행할 수 있다. 별도 설치·레지스트리 등록·드라이버·관리자 권한·자동 시작을 추가하지 않는다. 소스는 `02_제작_결과물/native/WhaleDualInput.Probe/`이고 현재 v0.2.0 제품 ZIP·확장앱에 섞이지 않는다.

자동 점검 명령:

```powershell
& .\dist\whale-dual-input\input-probe\WhaleDualInput.Probe.exe --self-test
& .\dist\whale-dual-input\input-probe\WhaleDualInput.Probe.exe --snapshot
& .\dist\whale-dual-input\input-probe\WhaleDualInput.Probe.exe --smoke-observe
```

`--snapshot`은 장치/화면 진단만 stdout에 출력한다. `--smoke-observe`는 1.2초 읽기 전용 Raw Input·커서/포커스 관찰을 시작·종료한다. 입력 차단·커서 제한·가짜 물리 입력은 실행하지 않는다. `--self-test`는 정책·좌표·ABI·버퍼 경계 검사이며 실제 보호 시험이 아니다.

## 화면 역할

이번 연구 구현에서 **Windows 주 화면=교사**, **유일한 보조 화면=학생**이다. Windows 설정의 표시 번호 1/2와 같다고 단정하지 않는다. **관찰은 복제·조회 불완전 구성에서도 실행 가능**하지만, 학생 창/학생 채널은 식별 가능한 보조 영역이 있을 때만 사용한다. 차단 시험은 두 화면 확장·겹침 없음·다른/미매핑 터치 없음이 필요하다. 세 화면 이상·복제·조회 실패에서 차단 버튼은 비활성화된다. 실제 수업 PC에서 주 화면이 교사 모니터인지 확인한다. 화면 역할을 안정적인 ID로 저장하고 재열거하는 작업은 후속이다.

Raw Mouse 장치 목록만으로는 칠판 매핑을 증명할 수 없다. `NO_MAPPED_POINTER_MOUSE_PATH_UNVERIFIED`는 마우스 에뮬레이션이 확인됐다는 뜻도, 지원 판정도 아니다. 이벤트로 출처/좌표를 확인해야 한다. 다른 화면의 터치·펜 또는 미매핑 포인터가 있으면 차단 시험을 거절한다.

## 실기기 시험 순서

1. 임시 메모장에 알려진 문장을 입력할 준비를 한다. 실제 학생 정보·업무 문서를 사용하지 않는다. Windows 주/보조 화면과 USB 터치를 확인한다.
2. 모니터 1에서 도구를 연 뒤 `화면·장치 다시 확인`을 누른다. 자동 판정과 실패 코드를 확인한다.
3. `입력 관찰 시작`으로 OFF 양성 대조군을 측정한다. 학생 시험 구간 버튼은 시간 표식이며 자동 귀속 판정은 아니다. 교사가 마커를 누를 때 생기는 포커스 변화와 실제 학생 터치 구간을 구분한다.
4. 학생이 시험 창 안과 밖을 터치하고 교사는 타이핑한다. PT_TOUCH/PT_PEN/RAW_MOUSE·호환 메시지·커서/포커스 변화를 비교한다. 시험 창 밖의 직접 포인터는 이 도구가 전역 수신하지 못한다.
   관찰 화면의 '커서 납치 가능'은 정상적인 경고다. 이 단계에서는 교사 커서가 움직여도 보호 엔진이 실행 중 실패한 것으로 해석하지 않는다. OFF 기준선의 간섭 재현으로 기록한다.
5. OFF로 관찰을 끝내고 진단을 저장한다. 학생 간섭을 실제로 잡아내지 못한 계측의 0건을 합격으로 쓰지 않는다.
6. 교사 커서를 주 화면 내부에 두고 `차단 후보 ON`을 명시적으로 누른다. 기본 확인 선택은 취소다. 시험은 최대 30초이며 F9/OFF로 중지한다. 기존 다른 프로그램의 커서 제한이나 F9 점유가 있으면 거절한다.
7. 모니터 1 경계 커서 점프, 잘못된 클릭, 타이핑 대상 변경, 직접 터치 누출을 관찰한다. 주 화면 제한 전후 훅 좌표가 달라지는지 로그로 비교한다. 보조 화면 학생 표시는 격리 증거가 아니다.
8. OFF/F9/30초 만료 후 두 화면에서 일반 마우스가 다시 움직이는지 확인한다. 장치 재연결/해상도 변경·잠금 시험은 시험 PC에서 별도로 수행한다. 오류가 나면 정상 해제로 표시하지 않는다.

검사 ID는 [모니터 1 보호 ADR](ADR_MONITOR1_PROTECTION_MODE.md)의 M1P-01~07을 쓴다. M1P-01의 100회·동시 타이핑과 M1P-02 경계 시험을 완료하기 전 실제 보호 성공이라고 하지 않는다.

## 알려진 경계

- Mouse hook는 물리 장치 핸들을 주지 않는다. 동시 교사 마우스/학생 마우스 에뮬레이션을 출처별로 완전히 분리하는 엔진이 아니다.
- ClipCursor 제한 후 칠판 좌표가 주 화면 경계로 바뀌면 화면 범위 필터가 놓칠 수 있다. 직접 터치/펜 입력은 별도 경로로 교사 포커스에 영향을 줄 수 있다.
- Raw Input 장치 핸들과 Pointer 장치 핸들이 같은 물리 장치인지는 아직 대조하지 않는다. 별칭을 동일시하지 않는다. Raw HID payload는 개인정보/범위 최소화를 위해 파싱하지 않는다.
- 주 화면+학생 시험 창만 제공한다. SEAT_*는 팝업 안의 직접 포인터만 대상으로 한다. 팝업 밖에서는 Raw Input/마우스 관측만 가능하며 전체 화면 터치가 학생 채널로 처리된다는 뜻이 아니다. 최종 제품은 팝업 없이 칠판 입력 전체를 격리·전달해야 한다.
- 이 도구는 Whale 웹페이지 조작을 전달하지 않는다. 기존 확장앱과 연결 전 원본 격리의 실기기 증거가 필요하다.
- 훅은 Windows timeout으로 제거될 수 있다. 메시지 스레드가 살아 있다는 이유로 격리 생존을 확인했다고 하지 않는다.
- UI 응답 감시는 2초 기준이며 전용 훅 스레드가 메시지를 처리하는 동안만 정리가 가능하다. 프로세스 전체 강제 종료·보안 데스크톱에서 연속 보호·정리를 보장하지 않는다. 자동 커서 복원·전역 입력 재주입은 없다.
- 4ms는 목표 샘플 주기이며 Windows 스케줄링으로 늦어질 수 있다. 짧은 간섭 전체를 검출한다고 주장하지 않는다. 타이핑 내용은 수집하지 않으므로 알려진 시험 문장 비교는 시험자가 수행한다.

## 데이터

최근 사건 최대 4096개를 메모리에 저장하고 덮어쓴 수를 표시한다. 장치/창은 실행 세션 내 별칭이다. 모델 문자열·장치 경로·시리얼·창 제목·URL·학생/교사 키 입력·전체 HID payload는 내보내지 않는다. 저장 버튼을 누른 파일에만 장치 유형·화면 geometry·이벤트 종류·좌표/시간·카운터를 기록한다. 외부 서버·자동 파일 저장은 없다. 사용자가 저장한 JSON은 직접 삭제할 수 있다. 계측 결과에는 시험 조건·시행 횟수·미탐·오탐·보호 공백을 함께 기록한다.
