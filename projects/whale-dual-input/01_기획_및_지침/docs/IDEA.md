# 교육 문제와 MVP

작성일: 2026-10-07. 상태: 기획, 효과 검증 전.

## 문제 정의

교사와 학생이 같은 Windows PC에 연결된 업무 모니터와 전자칠판을 함께 사용할 때, 학생의 터치가 교사의 커서와 키보드 포커스를 바꾸는 문제를 웨일 내부 독립 입력으로 해결한다.

전자칠판은 PC의 외부 화면과 USB 터치 장치다. 전자칠판 자체 OS에서 별도 브라우저를 실행하는 상황을 전제로 하지 않는다.

## 대상과 기존 불편

학생은 칠판에서 수업 웹페이지를 탐색·조작하고, 교사는 같은 PC에서 관찰 기록·문서 작성·다음 수업 준비를 한다. 두 작업이 기존 입력 경로를 공유하면 한쪽이 조작하는 동안 다른 쪽이 작업을 멈춰야 할 수 있다.

## 확장앱이어야 하는 이유

선택된 웨일 웹페이지에 학생 클릭·드래그·스크롤을 전달하고, 해당 페이지의 입력란과 가상 키보드를 연결해야 한다. 일반 웹사이트만으로 Windows 입력 보호와 다른 사이트의 페이지 조작을 함께 처리할 수 있다고 가정하지 않는다.

Whale Sidebar는 교사가 현재 페이지와 함께 대상·상태·ON/OFF를 확인하는 창구다. Content Script는 학습 페이지 내부 가상 키보드를 제공한다. Windows 입력 분리는 별도 로컬 호스트가 맡는다. 확장앱 단독 배포로 요구 전체를 충족한다고 주장하지 않는다.

## 핵심 경험과 추가 기능 판단

MVP는 교사 입력을 유지하는 한 개의 웨일 독립 입력 세션이다. 필수 조작과 한글 가상 키보드를 포함하고 로그인·AI·서버는 추가하지 않는다.

새 기능은 교육 문제·브라우저 맥락·클릭 수·권한·수집 데이터·기기 부담·필수 여부를 함께 검토한다. 학생용 표시 포인터는 조작 위치 확인에, 상태 안내와 F9는 실행·해제에 도움이 될 때만 넣는다. 핵심 경험 없이 장식이나 분석 기능부터 추가하지 않는다.

## 기대 효과와 검증

학생의 웹 활동 중 교사가 기록과 준비를 이어가는 수업 흐름을 목표로 한다. 웨일 클래스·팀보드는 실제 시험 후 지원 범위를 표기한다. 교사 입력 보호, 사이트 동작, 설치 부담을 검증하기 전 범용성·무지연·완전 독립을 달성 결과로 홍보하지 않는다.
