# v1.1 구현 범위와 준비 단계 결정

2026-10-08. 상태: 요구사항·구현 경계 확정, 제품 기능 개편 전. [인계 패키지](../../../Whale_Dual_Input_Development_Handoff_v1_1/README_START_HERE.md), [아키텍처](ARCHITECTURE_V7_3_MONITOR2.md), [실행계획](DEVELOPMENT_PLAN_V1_WHALE_MONITOR2.md)를 기준으로 한다.

## 문제와 확장앱의 역할

교사와 학생이 Windows PC 한 대와 전자칠판을 함께 쓰는 상황에서 학생 터치가 교사 커서·입력 포커스를 바꾸는 문제를, 웨일 확장앱과 Windows 원본 입력 격리 프로그램이 학생 터치만 별도 웹 입력으로 전달하여 해결한다.

확장앱은 현재 Whale 웹 콘텐츠와 직접 연결하여 교사용 ON/OFF, 상태 확인, CDP 입력 전달을 맡는다. Windows 장치 격리는 설치형 프로그램의 책임이며, 웹페이지 포장이나 서버 기반 서비스로 대체하지 않는다.

## MVP

| 구분 | 범위 |
|---|---|
| Must Have | 자동 식별한 모니터 2 전자칠판의 원본 터치 격리 + Whale 웹 콘텐츠 전달 + 사이드바 ON/OFF. 교사 실마우스·키보드 보호(G1)가 우선 |
| Should Have | 실제 상태·실패 사유·복구 안내, 교사 일시 해제, 자동 좌표 갱신, 접촉 취소·재연결 |
| Could Have | G1 이후 학생용 탐색 UI·한글 키보드 고도화·멀티터치·선택적 논리 포인터 표시 |
| Not Now | 일반 Windows 앱 전체 독립 제어, 원래 Whale 탭바·주소창 직접 터치, 로그인·서버·AI 기능 |

최종 v1 목표에는 지원 웹 입력·한글·탐색이 포함된다. 위 분류는 구현 투자 순서이며 최종 G2 조건을 생략하는 뜻이 아니다.

## 시스템 책임

| 계층 | 책임 | 예정 위치 |
|---|---|---|
| C1 Probe / DisplayResolver | 포인터 출처·모니터·확장 구성·장치 매핑 및 양성 대조군 계측 | `02_제작_결과물/native/WhaleDualInput.Probe/`, 이후 Display 모듈 |
| C2 Isolation | 원래 Windows 커서·포커스 적용 전 터치 격리. Tier A/B는 게이트 뒤 선택 | `02_제작_결과물/native/WhaleDualInput.Isolation.A/` 후보 |
| C3 StudentInputCore / ProtectionStateManager | 유한 큐, 접촉·sequence·epoch, 실제 보호 상태, 회복 | `02_제작_결과물/native/` 별도 모듈 |
| NativeBridge | 제한된 명령·ACK·상태와 이벤트 중계, 허용 확장 ID 및 로컬 IPC 경계 | 기존 Host에서 단계적으로 분리 |
| Service Worker / C4 | 학생 창·탭 자동 바인딩, CDP 입력, Native 재동기화 | `02_제작_결과물/background/` |
| Content Script | 격리 스타일의 학생 도구, 입력란·페이지 최소 연결 | `02_제작_결과물/content/` |
| Sidebar | 교사의 시작·중지·일시 해제·오류·진단 표시 | 기존 `sidebar_action` 유지 |

이 표는 목표 구조다. 신규 Native 모듈·상태 관리자가 이미 구현됐다는 의미가 아니다. 프로브는 브라우저 JS 빌드에 포함되지 않도록 현재 제품 리소스 allowlist를 유지한다.

## 권한과 데이터

현재 `activeTab`, `scripting`, `debugger`, `nativeMessaging` 및 선택적 `https://*/*`, `http://*/*`를 그대로 보존한다. 새 권한·자동 주입은 추가하지 않았다. 사이트 이동 자동화에서 activeTab의 수명과 Content Script 재주입 범위를 조사하고, 좁은 대안·최초 사용자 승인·학교 정책을 확인한 다음 별도 권한 결정을 한다. '사이트 등록 없음'을 이유로 모든 페이지의 DOM을 감시하지 않는다.

학생 입력은 기능 처리에 필요한 메모리에서만 사용한다. 기본 진단은 오류·상태·개수·시간·지연 위주다. URL·창 제목·입력 문자·장치 경로 전체를 진단에 남기지 않는다. 장치 식별자는 프로브 실행 세션 안의 익명 별칭으로 내보낸다.

## 기능 추가 판단 7개

1. 교사 작업 중 학생 터치 간섭이라는 핵심 문제에 직접 연결된다.
2. 현재 Whale 웹 콘텐츠 입력·상태 제어에 브라우저 확장 API가 필요하다.
3. 사이트 등록·영역 드래그를 없애 일상 사용을 ON/OFF로 줄인다.
4. 준비 단계의 권한 추가는 0개. 자동 탐색용 권한은 구현 근거 확보 후 검토한다.
5. 학생 데이터 수집을 늘리지 않는다. 진단 내용은 최소화한다.
6. 대형 UI 라이브러리 없이 전용 입력 루프·유한 큐·이벤트 기반 처리를 우선한다.
7. 장치 격리·보호 상태 없이는 핵심 경험이 완성되지 않는다. 가상 커서·탐색 꾸미기는 G1 뒤로 둔다.

## 완료 판정

M0 문서 준비와 제품 완료를 구분한다. G1·G2·실제 Whale·설치/운영 검증 전에는 ACTIVE 보증·일반 배포 준비·완성본으로 표현하지 않는다. 시험 ID는 연결본 [ACCEPTANCE_TESTS_V1_1](ACCEPTANCE_TESTS_V1_1.md)를 우선 사용한다. 원문 실행계획의 같은 번호가 다른 시험을 가리킬 수 있으므로 결과에는 문서명과 버전도 적는다.
