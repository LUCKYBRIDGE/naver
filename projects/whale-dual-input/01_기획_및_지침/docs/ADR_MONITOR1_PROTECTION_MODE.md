# ADR: 모니터 1 교사 보호 / 모니터 2 학생 전용 모드

2026-10-13. 상태: **사용자 요구 변경 채택, 구현 경로는 후보 / G1·G2 NOT TESTED**. v7.3 원문은 보존하고 이 ADR로 변경된 조건만 덧붙인다.

## 사용자 결정

사용자는 '모니터2에 대해 교사가 입력하는걸 다 막아도 괜찮아. 다만 모니터1에서 해당 기능을 on/off만 잘 할 수 있으면 돼'라고 명시했다. 이는 기존 '교사 실마우스가 모니터 1·2 어디서나 정상 조작' 조건을 완화한다. 교사 입력을 두 화면에서 보존해야 한다는 이유로 화면 경계 차단을 배제한 기존 결정도 재검토할 수 있다.

## 채택할 제품 동작

| 상태 | 교사 | 학생 | 제어/복구 |
|---|---|---|---|
| OFF | 일반 Windows 입력 | 일반 Windows 터치 | 모니터 1에서 ON 가능 |
| ON 준비 | 모니터 1 작업 유지 | 보호 확인 전 작동 성공 표시 없음 | 취소·비상 해제 접근 가능 |
| ACTIVE | 모니터 1 업무·커서·클릭·타이핑, 모니터 2 조작 제한 허용 | 모니터 2의 학생 논리 입력을 Whale 지원 콘텐츠로 전달 | 모니터 1에서 OFF, 물리 키보드 비상 해제 |
| 보호 미확인/상실 | 보호 성공으로 표현하지 않음 | 입력 전달 중단/위험 안내 | 살아 있는 교사 중지·복구 수단 |

모니터 1에 커서를 '고정'하지 않는다. 교사는 그 화면 안에서 자유롭게 움직이고 클릭한다. 학생 터치가 모니터 1 경계로 교사 커서를 밀거나 모니터 1에 클릭을 발생시키는 것도 실패다. 교사 타이핑의 Windows 전경·내부 입력 포커스가 학생 입력 때문에 바뀌면 실패다.

Whale 사이드바 제어는 모니터 1에서 사용할 수 있어야 한다. 모니터 2 전체 차단 후보를 사용하면서 같은 화면의 OFF 버튼만 제공하는 구조는 채택하지 않는다. 지원 입력 대상은 기존 Whale 일반 콘텐츠 범위이며 일반 Windows 앱 전체를 학생 포인터로 제어하는 요구가 추가된 것은 아니다.

## 달라지는 기술 선택

드라이버 없이 시험할 후보로 '교사 커서의 모니터 1 영역 제한 + Windows 기본 마우스 경로의 모니터 2 조작 차단 + 별도 학생 입력 수집/전달'을 검토할 수 있다. 교사 실마우스도 모니터 2에서 막히는 동작은 새 요구 아래 허용된다. 입력 장치 출처·좌표 매핑·교사 포커스 보호 검증은 계속 필요하다.

이 후보의 성공은 **가설**이다. 기존 TouchOverlay/ScreenSelection 또는 과거 V5 문서가 새 조건을 만족한다고 확정하지 않는다. 제조사·VID/PID 하드코딩 없이 표준 입력을 자동 판별하고, 지원 경로가 확인되지 않은 장치는 미지원으로 처리한다.

## API 근거와 남은 위험

- [ClipCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-clipcursor)는 공유 커서를 지정 사각형에 제한한다. 범위 밖 이동은 사각형 안으로 조정될 수 있다. 따라서 모니터 2의 절대좌표 입력이 모니터 1 경계의 커서 이동으로 바뀌지 않는지 계측해야 한다. 이 API만으로 클릭·터치·포커스 차단을 주장하지 않는다.
- [LowLevelMouseProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)는 마우스 메시지가 스레드 입력 큐로 전달되기 전 호출되며 nonzero 반환으로 전달을 막을 수 있다. 직접 터치/펜 경로 전부를 가로챈다는 근거가 아니다. 훅 timeout 시 조용히 제거될 수 있으므로 하트비트만으로 보호가 살아 있다고 확정하지 않는다.
- [RAWINPUTDEVICE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawinputdevice)의 NOLEGACY는 해당 애플리케이션의 레거시 메시지 정책이다. Raw Input 수집/등록으로 Windows 전체의 원본 입력 차단을 대체하지 않는다.

ClipCursor와 훅을 같이 쓸 때 훅 좌표가 범위 제한 전·후 어느 좌표인지, 이동이 실제로 차단되는지, 터치발 호환 마우스·직접 포인터 경로가 함께 발생하는지는 실측한다. 제한 후 좌표가 모니터 1로 바뀌었다면 '모니터 2 좌표만 차단' 규칙이 유입을 놓칠 수 있다. 학생 입력을 읽기 위한 좌표를 공유 시스템 커서의 제한된 위치에서 얻지 않는다.

교사 키보드의 Alt+Tab, 보안 화면, 앱의 자발적인 포커스 변경은 학생 터치 간섭과 구분해 관측한다. 포커스가 모니터 2로 이동하는 상황에서 모든 키보드를 무차별 차단하는 방법을 기본 정책으로 도입하지 않는다. 모니터 1 제어·해제가 불가능해질 수 있다. 처리 정책은 실제 보호 후보의 결과로 별도 확정한다.

## 유지되는 원칙

- 커서가 움직인 뒤 SetCursorPos로 되돌리거나 SetForegroundWindow로 포커스를 복구하여 성공처럼 표시하지 않는다.
- 입력 격리와 학생 포인터 표시를 구분한다. ACTIVE는 실제 보호·매핑·어댑터 확인 뒤만 발급한다.
- STOP/PAUSE는 실제 정리·해제 ACK 뒤 상태를 확정한다. OFF·비상 해제에서 이 프로그램의 커서 제한·후크·접촉을 정리하고, 이전 제한의 소유/복구를 고려한다.
- 보안 데스크톱·강제 종료·화면 분리의 보호 연속성은 별도 시험한다. 기본 입력으로 복귀했다면 보호 상실을 숨기지 않는다.
- Native 구성요소와 최소 권한 MV3 확장 구조를 유지한다. 이번 ADR은 권한 확대·드라이버 설치 승인이나 실제 보호 기능 구현이 아니다.

## 다음 개발 단위와 판정

1. 관찰 전용 Probe에서 터치/펜/마우스 타입·장치 출처·화면 매핑을 기록하고 OFF 양성 대조군을 확보한다.
2. 모니터 1 제어창·ON/OFF·물리 키보드 비상 해제를 먼저 갖춘다. 자동 화면 식별 실패 시 제한/차단을 적용하지 않는다.
3. 최소 커서 제한/차단 후보는 처음에 학생 웹 전달 없이 시험한다. 필요 없는 전역 키보드 후크나 입력 재주입을 추가하지 않는다.
4. 모니터 1 보호가 실제 통과하면 학생 채널·논리 포인터·Whale CDP를 연결하고 같은 동시 작업 시험을 반복한다.
5. 직접 터치·마우스 에뮬레이션 중 하나라도 새면 경로별 원인을 기록한다. 필요하면 기존 Tier A/B를 계속 검토하며, 실패를 새 커서 표시로 가리지 않는다.

| 시험 ID | 필수 관측 |
|---|---|
| M1P-01 | 학생 100회 터치 중 모니터 1 커서 위치·클릭·전경/내부 포커스·타이핑 간섭 0건 |
| M1P-02 | 모니터 1 경계 가까이에 교사 커서를 둔 채 칠판 모서리·드래그·길게 누르기 시험 |
| M1P-03 | 교사 모니터 2 이동/클릭 시도는 제한되어도 되지만 모니터 1 조작은 정상 |
| M1P-04 | 제한 전/후 마우스 훅 좌표, 직접 WM_POINTER/WM_TOUCH, 호환 WM_MOUSE 경로 비교 |
| M1P-05 | 모니터 1에서 ON/OFF·취소·F9, 브리지/Worker 단절 및 Native 종료 후 복구 |
| M1P-06 | 확장/복제·음수 화면 좌표·배율·회전·USB 재연결·터치 잘못 매핑에서 임의 시작 없음 |
| M1P-07 | 학생 포인터/웹 입력이 교사 커서·OS 포커스를 변경하지 않으며 중복 클릭 없음 |

기존 QA의 '교사 모니터 2 자유 클릭' 합격 항목은 이 모드에서 M1P-03으로 대체한다. 나머지 G1·G2·개인정보·설치 조건을 생략하지 않는다. 로그에 사용자 입력 문자·페이지 URL·창 제목을 저장하지 않는다.

## 현재 결과

2026-10-13 구현 업데이트: [관찰 도구](INPUT_PROBE_RUNBOOK.md)에서 자동 장치/화면 조회·Raw Input/커서/포커스·학생 접촉 채널과 별도 마우스 차단 후보를 구현했다. 사용자 터치 관찰 결과는 [M0_5_MEASUREMENT](M0_5_MEASUREMENT.md)에 기록했다. 팝업 안의 연구 채널은 동작하지만 칠판 입력 전체 원본 차단·Whale 전달은 아직 연결하지 않았다. 관찰에서 커서 간섭 사용자 보고가 있으며 이를 보호 성공으로 해석하지 않는다.

요구와 검토 후보만 기록했다. 구현·후크 실행·커서 제한·실제 칠판 시험은 미수행이다. **G1/G2 NOT TESTED.** 원본 v7.3·인계 폴더와 미추적 ARCHITECTURE_V5.md는 변경하지 않았다.

위 문단은 ADR 최초 작성 시점의 기록이다. 구현 이후에는 앞의 업데이트와 실제 관찰 결과를 우선한다. 차단용 훅·커서 제한의 물리 시험 및 G1/G2는 계속 미검증이다.
