# Whale Dual Input 개발기획안 v3.0
## 전자칠판 미러링/확장 환경 기반 웨일 브라우저 독립 입력 시스템

> **기획 이력 안내 (2026-10-07):** 이 문서는 초기 기획을 보존한 v3입니다. 현재 구현 기준은 [구현 준비 및 개발 계획 v4](whale_dual_input_implementation_plan_v4.md)입니다. 아래의 훅 차단만으로 커서·포커스를 완전히 보호한다는 설명과 무지연 표현은 아직 검증되지 않은 가설·목표이며, v4의 실기기 검증 단계를 우선합니다.

- **문서 버전:** v3.0 (실제 교실 하드웨어 환경 및 제어창 반영)
- **작성일:** 2026-10-07
- **환경 정의:** 교사 PC(Windows 10/11) + 전자칠판(USB 터치 + HDMI 디스플레이 미러링/확장) + NAVER Whale
- **최우선 절대 원칙:** 
  > **교사의 물리 마우스와 키보드는 기존 Windows에서 100% 정상 작동하며, 학생이 전자칠판에서 조작하는 터치와 가상 키보드는 시스템 커서 이동이나 포커스 탈취 없이 지정된 웨일 브라우저 창에만 독립적으로 작동한다.**

---

# 1. 문제의 본질 및 해결 정의

### 1.1 실제 교실 환경의 문제 (The Problem)
- 전자칠판은 자체 OS 모드가 아니라, **교사 PC 화면을 그대로 비추는(복제/확장) 모니터**로 작동하고 있으며, 터치 신호는 USB 케이블을 통해 Windows로 전달됩니다.
- Windows는 기본적으로 전자칠판의 터치를 **"PC의 유일한 마우스(System Cursor)"**로 자동 변환(Touch-to-Mouse Synthesis)합니다.
- **결과적인 참사:** 학생이 칠판을 터치하는 순간, 교사가 작업 중이던 마우스 커서가 칠판 위치로 순간이동하고, 한글/PPT/성적처리 창의 키보드 포커스가 강제로 풀려버립니다.

### 1.2 우리가 만드는 해결책 (The Solution)
- **독립 제어창(GUI):** 교사가 원클릭으로 `[독립모드 ON / OFF]`를 제어할 수 있는 별도의 프로그램 제어창을 제공합니다.
- **터치/마우스 분리 필터링:** 독립모드가 켜지면, 전자칠판의 USB 터치가 시스템 커서를 납치하려는 시도를 OS 수준에서 가로채 차단하고, 해당 터치 신호만 **지정된 웨일 브라우저 창 내부 이벤트로 직결**시킵니다.
- **웹 내부 팝업 가상 키보드:** 웨일 브라우저 웹페이지 안에 터치 친화적인 가상 키보드가 팝업으로 떠서, 칠판 터치만으로 한글/영문/숫자를 입력할 수 있게 합니다 (Windows OSK나 SendInput 미사용).
- **교사 자유도 보장:** 교사는 물리 마우스와 키보드로 자신의 모니터에서 평소처럼 아무 프로그램이나 자유롭게 작업합니다.

# 3. 기술적 핵심 해결 원리 (어떻게 가능한가?)

### 3.1 물리 마우스와 칠판 터치의 완벽한 구별
Windows User32는 터치 디지타이저가 발생시킨 합성 마우스 이벤트에 고유한 하드웨어 플래그를 찍어 보냅니다:

```csharp
// Windows 저수준 마우스 훅(WH_MOUSE_LL) 내 판별 공식
const uint MOUSEEVENTF_FROMTOUCH = 0xFF515700;
bool isBlackboardTouch = (hookStruct.dwExtraInfo & 0xFFFFFF00) == MOUSEEVENTF_FROMTOUCH;
```

- **교사의 물리 마우스:** `isBlackboardTouch == false` (Zero 차단, 즉시 통과, 0ms 지연)
- **전자칠판의 USB 터치:** `isBlackboardTouch == true` (터치 서명 감지)

### 3.2 시스템 커서 고정 및 포커스 보호
- `isBlackboardTouch == true`이고 터치 좌표가 독립모드 웨일 창 내부인 경우:
  1. 마우스 후크에서 **`return 1` (차단)**을 호출합니다.
  2. Windows OS는 시스템 커서를 터치 위치로 이동시키지 못하며, 창 활성화(`WM_MOUSEACTIVATE`)도 발생하지 않습니다.
  3. 교사의 시스템 커서는 원래 위치에 그대로 남아있고, 커서 숨김(`CURSOR_SUPPRESSED`)도 발생하지 않습니다.
  4. 동시에 우리 백그라운드 Agent가 해당 좌표를 웨일 창 내부의 클릭/터치 명령으로 전달합니다.

### 3.3 웹페이지 내 팝업 가상 키보드 (In-Page Virtual Keyboard)
- 학생이 웨일 브라우저 화면의 검색창이나 입력란을 터치하면:
- 웨일 확장 프로그램(Content Script)이 감지하여 웹페이지 내부에 **터치 전용 가상 키보드 팝업(Shadow DOM)**을 띄웁니다.
- 칠판에서 이 가상 키보드의 자판을 터치하는 행위도 웨일 창 내부의 독립 터치로 처리됩니다.
- 자체 한글 음소 조합기(Hangul Composer)가 작동하여 입력창에 글자를 완성합니다.
- **결과:** Windows 전역 키 입력(`SendInput`)을 1바이트도 발생시키지 않으므로 교사가 타이핑 중이던 문서에 학생의 글자가 섞여 들어가는 일이 원천 차단됩니다.

# 4. 프로그램 제어창 GUI (Teacher Control Center)

교사가 직관적으로 조작할 수 있는 독립 제어창을 제공합니다.

### 4.1 제어창 UI 구성
```text
┌────────────────────────────────────────────────────────┐
│  🐳 웨일 듀얼 인풋 컨트롤러 (Teacher Control Center)   │
├────────────────────────────────────────────────────────┤
│                                                        │
│   [ 웨일 브라우저 독립모드 ]                           │
│   ┌──────────────────────────────────────────────┐     │
│   │               [  ON  /  OFF  ]               │     │
│   └──────────────────────────────────────────────┘     │
│                                                        │
│   • 대상 웨일 창: [웨일 브라우저 (0x00B2A4)] [창 새로고침]  │
│   • 현재 모드: 칠판 터치 독립 격리 작동 중            │
│                                                        │
├────────────────────────────────────────────────────────┤
│   📊 실시간 동작 상태                                  │
│   - 교사 마우스/키보드: 정상 사용 중 (포커스 유지)     │
│   - 학생 칠판 터치 감지: 154 회                        │
│   - 차단된 커서 탈취 시도: 154 회                      │
│                                                        │
│   [ 단축키 안내: F9를 누르면 즉시 독립모드가 해제됩니다 ]│
└────────────────────────────────────────────────────────┘
```

### 4.2 모드별 동작 정의
- **독립모드 [ON]:**
  - 전자칠판의 터치는 웨일 브라우저 내부 조작(터치/스크롤/가상키보드)으로만 동작.
  - 교사 마우스 커서는 터치 위치로 튀지 않고 기존 작업 유지.
- **독립모드 [OFF]:**
  - 모든 후크 및 격리 해제.
  - 평소처럼 전자칠판 터치도 일반 Windows 마우스로 동작.

# 5. 한글 음소 조합기 (Hangul Composer) 설계

웹페이지 내 가상 키보드에서 칠판 터치만으로 완성형 한글을 입력하기 위한 오토마타 엔진입니다.

```text
[초성 입력] ──> [중성 입력 (단모음/이중모음)] ──> [종성 입력 (단자음/겹받침)]
      │                     │                               │
      └── (자음 추가)       └── (자음 입력 시 종성 전이)   └── (모음 입력 시 초성 분리)
```

- **지원 기능:**
  - 초성(19자), 중성(21자), 종성(27자) 표준 유니코드 조합
  - 이중모음 합성 (`ㅗ`+`ㅏ` = `ㅘ`, `ㅜ`+`ㅓ` = `ㅝ`, `ㅡ`+`ㅣ` = `ㅢ` 등)
  - 겹받침 합성 및 분해 (`ㄱ`+`ㅅ` = `ㄳ`, `ㄴ`+`ㅈ` = `ㄵ`, Backspace 시 분해 삭제)
  - 영문 / 숫자 / 특수기호 / 스페이스 / 엔터 지원
- **독립성 보장:**
  - 웹 DOM 대상 요소(`HTMLInputElement`, `HTMLTextAreaElement`)의 `value`와 `selectionStart/End`를 직접 갱신하고 `input`, `change` 이벤트를 디스패치합니다.
  - Windows IME를 거치지 않으므로 교사의 한/영 입력 상태와 100% 독립적입니다.

# 7. 절대 실패 조건 및 판정 기준 (Non-Negotiable Invariants)

다음 중 하나라도 발생하면 기술적 실패로 판정하며 즉시 개선 코드를 적용합니다:

1. **커서 튐 후 복원 방식 (Disallowed):**
   - 터치 위치로 커서가 이동했다가 0.1초 뒤 다시 원래 자리로 복원되는 방식은 실패로 규정합니다. (원천 차단만 인정)
2. **교사 키보드 문자 누락 (Disallowed):**
   - 교사가 한글 타이핑 중 학생이 가상 키보드를 누를 때, 교사의 글자가 누락되거나 학생 글자가 교사 문서로 들어가면 실패입니다.
3. **커서 숨김(Cursor Suppression) 발생 (Disallowed):**
   - 학생이 칠판을 터치하는 동안 교사 화면에서 마우스 커서가 사라져서 작업 흐름이 끊기면 실패입니다.
4. **교사 마우스 지연 (Disallowed):**
   - 훅 설치로 인해 교사 마우스에 1ms 이상의 체감 딜레이가 발생하면 실패입니다.
5. **비상 해제 실패 (Disallowed):**
   - `F9` 또는 제어창 `[OFF]` 클릭 시 즉시 100% 평상시 마우스 상태로 원복되어야 합니다.
